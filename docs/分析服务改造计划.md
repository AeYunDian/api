# 分析服务改造计划

> 范围：`mysites.undz.cn` 分析服务（采集 + 统计）与 `console.undz.cn` 站点管理。
> 目标：三态可见性、多域名、v2 数据表、服务模块化、mysites 脱敏站点列表。
> 本文件只写**计划**，不含代码改动。

## 1. 范围

### 1.1 本次要做

| # | 事项 | 涉及 |
|---|---|---|
| 1 | 站点可见性：`private` / `logged_in` / `public` + 独立 `listed` | 两服务 + 前端 |

## 2. 改造前基线

### 2.1 路由

| 方法 | 路径 | 服务 | 认证 |
|---|---|---|---|
| GET | `/analytics.js` | mysites | 无 |
| GET/POST | `/api/event` | mysites | 无（site token） |
| GET | `/api/sites/:id/stats` | mysites | Cookie |
| GET | `/api/sites/:id/realtime` | mysites | Cookie |
| GET | `/api/me` | mysites | Cookie |
| GET | `/api/console/sites` | console | Cookie |
| POST | `/api/console/sites` | console | Cookie |
| DELETE | `/api/console/sites/:id` | console | Cookie |
| PUT | `/api/console/sites/transfer` | console | Cookie + admin |

现状约束：`/api/` 下所有路径在进入业务前先 `checkAuth`，未登录直接 401（`ayAnalytics.js:744-755`），所以匿名看公开统计页走不通。本次**不新增公开路由前缀**，而是把这个全局 401 拆掉：认证照旧做，但「要不要登录」交给每个接口自己判断（§6.1）。

### 2.2 代码与表

- `api-worker/src/services/analytics/ayAnalytics.js` 单文件 812 行：常量、CORS、UA 解析、跟踪器模板、上报、统计、实时、入口全在一起。
- `analytics_sites`：`id, token, user_sub, domain, name, created_at, updated_at`；`token`、`domain` 各一个唯一索引。
- `analytics_events`：`site_token, ts, visitor, name, path, ref, country, browser, os, device, screen, utm_*`；索引 `(site_token, ts)`、`(site_token, path)`。
- `console/routes/sites.js` 当前只支持单 `domain`、无可见性字段，写的是 `analytics_sites`。
- 前端 `api-vue/src/mysites/views/HomeView.vue` 目前登录后跨域调 console 取「我的站点」；`SiteOverview.vue` 直接读 `data.totals.*`、`data.breakdowns.*`。

### 2.3 限流器分工

| binding | 配额 | 用途 | 现状 |
|---|---|---|---|
| `analy_limiter` | 20 次 / 10 秒 | **本服务上报专用**（`wrangler.toml:25-31` 已加） | 代码零引用 |
| `limiter` | 50 次 / 10 秒 | 统计、实时（以及其他服务共用） | 上报/统计/实时都在用 |

改造后的分工固定为：

| 通道 | binding | key | 超限 |
|---|---|---|---|
| 上报 `/api/event` | `analy_limiter` | `evt:${ip}` | **201**（空 body） |
| 统计 `/api/sites/:id/stats` | `limiter` | `stats:${sub}`，匿名 `stats:anon:${ip}` | 429 |
| 实时 `/api/sites/:id/realtime` | `limiter` | `rt:${sub}`，匿名 `rt:anon:${ip}` | 429 |
| 站点目录 `/api/sites`、元信息 `/api/sites/:id` | `limiter` | `sites:${ip}` | 429 |

上报从 `limiter` 移出后，只占 `analy_limiter` 的配额，不再和统计抢额度。

## 3. 可见性模型

### 3.1 三态矩阵

| visibility | 语义 | `listed` 允许 | 匿名 | 登录非 owner | owner/admin |
|---|---|---|---|---|---|
| `private`（默认） | 仅自己 | 恒 0 | 404 | 404 | 全部数据 |
| `logged_in` | 登录可看 | 0 或 1 | 401 | 按 `share_config` | 全部数据 |
| `public` | 任何人可看 | 0 或 1 | 按 `share_config` | 按 `share_config` | 全部数据 |

服务端强制规则：

1. `private` → `listed := 0`，忽略请求值。
2. `listed = 1` 仅允许 `logged_in` / `public`；非法组合静默降级为 0，不报错。
3. `visibility` 非法值 → 回落 `private`。
4. 编辑时按「目标 visibility」归一化 `listed`，**即使请求里没带 `listed`**（只把 visibility 改成 private 也必须把 listed 写 0）。

### 3.2 `listed` 与可见性的关系

| 场景 | visibility | listed | 谁能在 mysites 目录看到 |
|---|---|---|---|
| 完全私密 | `private` | 0 | 无人 |
| 登录可见、公开列出 | `logged_in` | 1 | 登录用户（console 列表） |
| 登录可见、不列出 | `logged_in` | 0 | 无人（凭直链也要登录） |
| 公开、进目录 | `public` | 1 | 任何人（`/api/sites`） |
| 公开、不进目录 | `public` | 0 | 只有拿到直链的人 |

mysites 的 `/api/sites` 不需要登录，但会读 Cookie：`public` 区块中，匿名访客取上表第 4 行（`listed = 1 AND visibility = 'public'`），登录用户还要**排除 `user_sub = 自己`**（自己的站点只放 `mine` 区块），管理员取全部站点；`mine` 区块只有带有效 Cookie 才有内容。第 2 行（`logged_in + listed=1`）不进公开区块，只可能出现在本人的 `mine` 和 console 的登录态列表里。

### 3.3 状态迁移

```
private ──设为 public/logged_in──► public / logged_in
public  ──关闭 listed───────────► public + listed=0     ← 「只给拿到链接的人看」
任意    ──设为 private──────────► private（listed 自动归零）
```

### 3.4 为什么没有 `unlisted`

「凭链接、不进列表」由 `public + listed=0` 表达：站点 id 不可枚举，`listed=0` 使其不出现在任何目录，链接只到知道 id 的人手里。再引入第四态和分享令牌，会多出生成、轮换、撤销、泄漏四类状态，收益不抵成本。若将来确实需要「按人撤销的链接」，应单建 `analytics_site_shares` 表，不要把令牌塞进站点表。

## 4. 数据表 v2

### 4.1 `analytics_sites_v2`

```sql
CREATE TABLE IF NOT EXISTS analytics_sites_v2 (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  token        TEXT    NOT NULL UNIQUE,
  user_sub     INTEGER NOT NULL,
  domain       TEXT    NOT NULL,              -- 冗余：domains[0]
  domains      TEXT    NOT NULL DEFAULT '[]', -- JSON 数组
  name         TEXT    NOT NULL,
  visibility   TEXT    NOT NULL DEFAULT 'private',
  listed       INTEGER NOT NULL DEFAULT 0,
  share_config TEXT    NOT NULL DEFAULT '{}',
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_asv2_domain ON analytics_sites_v2(domain);
CREATE INDEX IF NOT EXISTS idx_asv2_user   ON analytics_sites_v2(user_sub);
CREATE INDEX IF NOT EXISTS idx_asv2_listed ON analytics_sites_v2(listed, visibility);
```

- `domain` 保留为 `domains[0]` 的冗余副本，旧查询与唯一索引继续可用。
- `idx_asv2_listed` 服务于 `/api/sites` 与 console 的公开列表查询，避免全表扫描。
- `token` 继续由 `shared/utils.js` 的 `generateToken()` 生成（32 字节 hex）。

### 4.2 `analytics_events_v2`

```sql
CREATE TABLE IF NOT EXISTS analytics_events_v2 (
  site_token       TEXT    NOT NULL,
  ts               INTEGER NOT NULL,
  visitor          TEXT    NOT NULL,
  session_id       TEXT    NOT NULL DEFAULT '',
  name             TEXT    NOT NULL,
  path             TEXT    NOT NULL,
  ref              TEXT    NOT NULL DEFAULT '',
  country          TEXT    NOT NULL DEFAULT '',
  province         TEXT    NOT NULL DEFAULT '',
  browser          TEXT    NOT NULL DEFAULT '',
  browser_version  TEXT    NOT NULL DEFAULT '',
  os               TEXT    NOT NULL DEFAULT '',
  os_version       TEXT    NOT NULL DEFAULT '',
  device           TEXT    NOT NULL DEFAULT '',
  screen           TEXT    NOT NULL DEFAULT '',
  touch_points     INTEGER NOT NULL DEFAULT 0,
  utm_source       TEXT    NOT NULL DEFAULT '',
  utm_medium       TEXT    NOT NULL DEFAULT '',
  utm_campaign     TEXT    NOT NULL DEFAULT '',
  utm_term         TEXT    NOT NULL DEFAULT '',
  utm_content      TEXT    NOT NULL DEFAULT ''
);

CREATE INDEX IF NOT EXISTS idx_aev2_token_ts      ON analytics_events_v2(site_token, ts);
CREATE INDEX IF NOT EXISTS idx_aev2_token_name_ts ON analytics_events_v2(site_token, name, ts);
CREATE INDEX IF NOT EXISTS idx_aev2_token_path    ON analytics_events_v2(site_token, path);
```

设计要点：

1. 不用 `INTEGER PRIMARY KEY AUTOINCREMENT`，直接吃隐式 `rowid`；D1 按行计费，省一列是一列。
2. `(site_token, ts)` 覆盖「pageview + 时间范围」；额外 `(site_token, name, ts)` 让自定义事件也走索引。
3. `province` 只在 `country='CN'` 时写入；`CN_ONLY` 裁剪靠 `country` 过滤，不靠 `province`。
4. 所有字符串列在代码层 `clamp`，DDL 不加 CHECK：分析数据是 best-effort，宁可截断也不要 500。

### 4.3 字段来源

| 字段 | 来源 | 说明 |
|---|---|---|
| `country` | `request.cf.country` | 本地/预览为空串 |
| `province` | `request.cf.regionCode \|\| request.cf.region` | 需 `CN 省名/省码 → 两位码` 映射；映射不到留空。**上线前用真实流量采样确认该字段在 CN colo 的取值形态**，这是全篇唯一需要实测的点 |
| `browser`/`os`/`device` | 现有 `parseUa()` | 命中 `BOT_RE` 直接丢弃 |
| `browser_version`/`os_version` | 现有正则捕获组 | `Edge/120.0.1` → `120`；取不到留空 |
| `screen` | 现有 `screenBucket(w)` | 宽度分桶 |
| `touch_points` | `navigator.maxTouchPoints` | 客户端新增；只接受 0/1/2/5/10，其余归 0 |
| `session_id` | 客户端每次页面加载生成 12 hex | SPA 路由切换复用；`sessions` = `COUNT(DISTINCT session_id)` |
| `visitor` | 现有 `visitorHash(day, token, ip, ua)` | 每日轮换，IP/UA 不落库 |
| `utm_*` | 落地 URL 查询参数 | 5 个，各 `clamp 255` |

### 4.4 数据由站长手工迁移

代码不提供迁移逻辑，不读写旧表。新表上线后为空，面板也会是空的，直到数据被搬过来。参考思路（不由代码执行）：

1. `analytics_sites` → `analytics_sites_v2`：`domains = json_array(domain)`，`visibility='private'`，`listed=0`，`share_config='{}'`。
2. `analytics_events` → `analytics_events_v2`：列名基本对齐，缺失列走默认值。
3. 旧表保留，不做 `DROP`；确认新表可用后再自行处理。

## 5. 服务拆分

### 5.1 目标结构（对齐 `console` / `account` 的拆分方式）

```
api-worker/src/services/analytics/
├── ayAnalytics.js        # 入口：OPTIONS、认证分流、按路径分发（≈110 行）
├── config.js             # 域名白名单、token 正则、body 上限、TABLES 常量、限流 key
├── http.js               # jsonResponse / corsHeaders / CORS_OPEN
├── utils.js              # clamp / safeParseArray / safeParseObject
├── db.js                 # 只放 SQL：站点与事件的读写函数
├── access.js             # resolveAccessContext、parse/sanitizeShareConfig
├── domains.js            # normalizeDomain、buildDomainsList、getSiteDomains、唯一性检查
├── ua.js                 # parseUa、BOT_RE、versions、screenBucket、province 映射
├── tracker.js            # TRACKER_TEMPLATE、buildTrackerScript、randomId
├── routes/
│   ├── ingest.js         # GET/POST /api/event
│   ├── sites.js          # GET /api/sites（双区块脱敏列表）、GET /api/sites/:id（元信息）
│   ├── stats.js          # GET /api/sites/:id/stats、/realtime
│   └── me.js             # GET /api/me
└── README.md             # 端点表、鉴权、限流、表名（对齐 console/README.md）
```

### 5.2 模块职责

| 模块 | 内容 | 约束 |
|---|---|---|
| `config.js` | 常量与表名 | 不 import 业务模块，避免环依赖 |
| `http.js` | 响应/CORS | 只依赖 Request，无 D1 |
| `db.js` | SQL | 每个函数单一用途；表名用 `TABLES.*` 拼接；不抛业务错误，返回数据或 `null` |
| `access.js` | 权限与分享配置 | 唯一权限入口；不写裸 SQL，调用 `db.js` |
| `domains.js` | 域名处理 | 纯函数 + 一次唯一性查询（查询走 `db.js`） |
| `routes/*.js` | HTTP 层 | 入参校验、调用 `access`/`db`、组织响应；不写裸 SQL |
| `ayAnalytics.js` | 入口 | 只做分流与认证，不写业务逻辑 |

### 5.3 入口分发顺序

```
OPTIONS            → /api/event 用 CORS_OPEN；其余用 corsHeaders
GET /analytics.js  → tracker
GET|POST /api/event→ routes/ingest（无认证，analy_limiter）
/api/sites         → routes/sites（无认证，limiter）
/api/sites/:id     → routes/sites（元信息：按可见性决定 200/401/404）
/api/sites/:id/stats|realtime → routes/stats（认证可选，limiter）
GET /api/me        → routes/me（必须登录，否则 401）
其余               → env.assets.fetch
```

### 5.4 拆分纪律

1. **先纯搬运，再改行为**：第一次提交只做文件切分、`import/export` 和表名常量替换，`git diff` 应能逐行对照；行为变更（可见性、限流、多域名）单独提交。
2. 拆分阶段不顺手重命名函数、不改 SQL 语义，降低回归风险。
3. 拆分后 `docs/analytics.md` 的端点表同步更新。
4. 每个 `routes/*.js` 统一签名，与 console 一致：`handleXRoutes({ request, env, url, path, method, cors, user, isAdmin })`，未命中返回 `null`。

## 6. 接口与授权

### 6.1 授权下沉

不再对 `/api/*` 一刀切 401。入口只做两件事：

```js
const hasCookie = request.headers.has("Cookie");
const [authStatus, user] = hasCookie
  ? await checkAuth(request, env)
  : [TAG_NOT_LOGGEDIN, null];

if (authStatus === TAG_BANNED) return 403;   // 封禁对所有接口生效
// 不在此处返回 401，交给各 routes
```

| 接口 | 匿名访问 | 说明 |
|---|---|---|
| `/api/event` | 允许 | 靠 site token |
| `GET /api/sites` | 允许（Cookie 可选，决定 `mine`） | 两个脱敏区块：公开站点 + 我的站点 |
| `GET /api/sites/:id` | 允许，按可见性返回 200/401/404 | 元信息 |
| `GET /api/sites/:id/stats` | 允许，按可见性裁剪 | 公开分享的核心 |
| `GET /api/sites/:id/realtime` | 允许，需 `share_config.realtime` | 403 `not_shared` |
| `GET /api/me` | 拒绝，401 | 只有这个接口必须登录 |

无 Cookie 时跳过 `checkAuth`，匿名大流量（公开分享页）不会每次多打一次会话查询。Cookie 存在但过期/无效时，`checkAuth` 返回未登录，按匿名处理，不强制跳登录。

### 6.2 `GET /api/sites` —— 免授权双区块脱敏列表

作用：mysites 首页一次拿齐「公开站点」和「我的站点」。不带 Cookie 也能调，不会 401；带了 Cookie 才填 `mine`，并按身份调整两个区块的范围。

请求：

```
GET /api/sites
（Cookie 可选）
```

响应 `200`：

```json
{
  "public": [
    { "id": 3, "name": "我的博客", "domains": ["io.hb.cn", "undz.cn"] },
    { "id": 7, "name": "测试站",   "domains": ["test.undz.cn"] }
  ],
  "mine": [
    { "id": 9, "name": "内部看板", "domains": ["dash.undz.cn"] }
  ]
}
```

区块规则：

| 访问者 | `public` 区块 | `mine` 区块 |
|---|---|---|
| 匿名 | `listed = 1 AND visibility = 'public'` 的全部站点 | `[]` |
| 登录普通用户 | 同上，**但排除 `user_sub = 自己`** | `user_sub = 自己` 的全部站点（含 private / logged_in / public） |
| 管理员 | **全部站点**（不过滤自己的，含他人 private） | `user_sub = 1`，即管理员自己注册的站点 |

- 普通用户的公开区块严格不含自己的站点，自己的站点只在 `mine`；管理员两个区块允许重叠（自己的站点同时出现在两处），这是刻意保留的后台视角。
- 两个区块都脱敏，字段完全一致。
- 排序均 `created_at DESC`，各 `LIMIT 50`。

查询：

```sql
-- A. public 区块
--   匿名：不做 user_sub 过滤
--   普通用户：AND user_sub <> ?
--   管理员：去掉 WHERE 子句，取整表
SELECT id, name, domains, domain FROM analytics_sites_v2
WHERE listed = 1 AND visibility = 'public'
ORDER BY created_at DESC LIMIT 50;

-- B. mine 区块（仅当 user 非空）
SELECT id, name, domains, domain FROM analytics_sites_v2
WHERE user_sub = ?
ORDER BY created_at DESC LIMIT 50;
```

字段契约（**只这三个**）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 站点 id |
| `name` | string | 站点名 |
| `domains` | string[] | 数组；为空时回填 `[domain]` |

**明确不返回**：`token`、`user_sub`、`creator_username`（创建者只在详情接口按 `share_config` 返回）、`created_at`、`updated_at`、`share_config`、`visibility`、`listed`。管理需要的字段全部走 console 的 `/api/console/sites`。

- 限流：`env.limiter`，key `sites:${ip}`，超限 `429`。
- 无 Cookie 时跳过 `checkAuth`，本接口对匿名访客不产生会话查询。
- 站点管理仍在 console（`/api/console/sites`），本接口只读。

### 6.3 `GET /api/sites/:id` —— 公开元信息

```json
{
  "site": {
    "id": 3, "name": "我的博客",
    "domains": ["io.hb.cn"],
    "creator_username": "alice"
  },
  "access": { "level": "shared" },
  "share_config": { "totals": { "pageviews": true }, "series": false, "creator": true, "...": "..." }
}
```

- `public`：匿名可读。
- `logged_in`：匿名 `401 login_required`，且**响应里不含站点名**；登录后返回。
- `private`：非 owner 一律 404。
- 不含 `token`。
- **`creator_username`**：`share_config.creator === true` 时返回用户名；为 `false` 时返回 `null`。owner/admin 始终返回，不受该配置影响。
- 限流：`env.limiter`，key `sites:${ip}`，超限 429。

### 6.4 统计与实时

`GET /api/sites/:id/stats?range=`，身份由 `resolveAccessContext` 判断；owner/admin 可加 `as_guest=1` 以访客视角预览。

```json
{
  "site": {
    "id": 3, "name": "我的博客",
    "domain": "io.hb.cn", "domains": ["io.hb.cn", "undz.cn"],
    "visibility": "public", "listed": false,
    "creator_username": "alice",
    "token": "…仅 owner/admin…"
  },
  "range": { "id": "7d", "from": "2026-11-15", "to": "2026-11-21", "granularity": "day" },
  "access": { "level": "owner", "is_owner": true },
  "totals": { "pageviews": 1234, "visitors": 456, "sessions": 789 },
  "series": [ { "label": "2026-11-15", "pageviews": 10, "visitors": 8, "sessions": 9 } ],
  "breakdowns": {
    "path": [ { "val": "/", "pageviews": 100, "visitors": 50 } ],
    "referrer": [], "country": [], "province": [],
    "browser": [], "os": [], "device": [], "event": []
  }
}
```

约定：

- `totals` 三键始终存在，无权时 `null`；`breakdowns` 八键始终存在，无权时 `null`；`series` 无权时整体 `null`。
- breakdown 每项仍是 `{ val, pageviews, visitors }`，结构不变，前端只加 `null` 判断。
- `province` 为 `"CN_ONLY"` 时：`country` 查询加 `AND country='CN'`，`province` 查询加 `AND country='CN' AND province<>''`。
- **`site.token` 只对 owner/admin 返回**：分享者拿到 token 就能伪造上报。
- **`site.creator_username`**：owner/admin 始终返回；shared 访问者按 `share_config.creator`，为 `false` 时返回 `null`。
- 被裁剪的维度**不执行对应 SQL**，不是查完再丢。
- 限流：登录态 `stats:${user.sub}` / `rt:${user.sub}`；匿名 `stats:anon:${ip}` / `rt:anon:${ip}`。

### 6.5 console 站点管理

管理页面继续用原接口（路径与调用方式不变），表名切到 `analytics_sites_v2`，并补齐字段。

#### GET `/api/console/sites`

```sql
SELECT id, token, user_sub, domain, domains, name, visibility, listed,
       share_config, created_at, updated_at
FROM analytics_sites_v2
WHERE user_sub = ?                                   -- 管理员去掉此条件
   OR (listed = 1 AND visibility IN ('logged_in','public'))
ORDER BY created_at DESC;
```

逐条补充：`domains` 解析失败回填 `[domain]`；`share_config` 归一化；`is_owner = user_sub === user.sub`；`token` 仅 owner/admin 返回；`creator_username` 仅 owner/admin 返回（列表里不按 `share_config.creator` 裁剪，他人站点的创建者只在详情接口按配置出现）。

> 这里是「控制页面」的唯一入口，字段完整；mysites 的 `/api/sites` 只负责公开区块与自己站点的双区块展示，两者不互相替代。

#### POST `/api/console/sites`

```json
{
  "domain": "io.hb.cn",
  "domains": ["io.hb.cn", "undz.cn", "www.undz.cn"],
  "name": "我的博客",
  "visibility": "public",
  "listed": true,
  "share_config": { "totals": { "pageviews": true }, "series": true, "creator": true }
}
```

校验顺序：

1. `buildDomainsList()`：`domains` 优先，缺省 `[domain]`，`domain` 缺省 `domains[0]`；逐项规范化；非法项丢弃；去重；截断 10；空 → `400 invalid_domain`。
2. 配额：非管理员且已有 ≥5 → `403 site_limit`。
3. 全局唯一：任一域名被其他站点占用 → `409 domain_taken`（附占用者 `id`/`name`）。
4. `visibility` 白名单回落；`listed` 归一化。
5. `share_config` 归一化。
6. `INSERT`（`domain = domains[0]`）。

成功 `201`，返回完整站点对象。

#### PUT `/api/console/sites/:id`（新增）

允许：`name`、`visibility`、`listed`、`share_config`、`domains`。
禁止：`token`、`user_sub`（转移走 `/transfer`）。

1. `domains` 更新时重新规范化 + 全局唯一（排除自身 id），同步 `domain = list[0]`。
2. `visibility` 改 `private` 时 `listed` 一起写 0，无论请求是否带 `listed`。
3. `listed` 合法性按目标 visibility 判断。
4. 合并为一条 `UPDATE`，`updated_at = now`；无可更新字段 → `400 nothing_to_update`。
5. 权限：owner 或管理员；否则 `403 permission_denied`。

成功 `200`，返回更新后的完整站点对象。

#### DELETE / transfer

只改表名，逻辑不变。删除站点时同步删除 `analytics_events_v2` 中该 `site_token` 的行（两条语句 `env.db.batch`）。

## 7. `share_config` 规范

### 7.1 结构

```js
const DEFAULT_SHARE_CONFIG = {
  totals:   { pageviews: false, visitors: false, sessions: false },
  series:   false,
  realtime: false,
  creator:  true,   // 创建者展示，默认开启
  breakdowns: {
    path: false, referrer: false, country: false, province: false,
    browser: false, os: false, device: false, event: false,
  },
};
```

- 默认只开 `creator`，其余全关：页面不会是一片空白，至少能看到站点归属；统计维度仍需手动勾选。
- **至少一项必须为 true**：归一化后若全部为 false，后端强制 `creator = true`（§7.3），避免「分享出去却什么都没有」。
- 创建表单预勾选「推荐模板」（totals + series + 全部 breakdown），后端不猜意图。
- `creator` 在前端默认勾选且禁用，只有开发者选项可解锁（§9）；接口不额外校验谁能改它。
- `province` 三态：`false` / `true` / `"CN_ONLY"`。

### 7.2 裁剪语义

| 配置项 | `false` | `true` / `CN_ONLY` |
|---|---|---|
| `totals.pageviews` / `visitors` / `sessions` | 对应键 `null` | 数字 |
| `series` | `null` | 数组 |
| `realtime` | 公开实时 403 | 正常 |
| `creator` | `site.creator_username = null` | 创建者用户名 |
| `breakdowns.x` | `null` | 数组（≤20 项） |

被裁剪的项返回 `null`，不返回 `[]`、不删键：`[]` 必须保留「已分享但暂无数据」的含义。

### 7.3 归一化

```js
function sanitizeShareConfig(input) {
  const src = input && typeof input === "object" ? input : {};
  const t = src.totals && typeof src.totals === "object" ? src.totals : {};
  const b = src.breakdowns && typeof src.breakdowns === "object" ? src.breakdowns : {};
  const bool = (v) => v === true;

  const config = {
    totals: { pageviews: bool(t.pageviews), visitors: bool(t.visitors), sessions: bool(t.sessions) },
    series: bool(src.series),
    realtime: bool(src.realtime),
    creator: src.creator === undefined ? true : bool(src.creator), // 缺省开启
    breakdowns: {
      path: bool(b.path), referrer: bool(b.referrer), country: bool(b.country),
      province: b.province === "CN_ONLY" ? "CN_ONLY" : bool(b.province),
      browser: bool(b.browser), os: bool(b.os), device: bool(b.device), event: bool(b.event),
    },
  };

  // 至少一项为 true；全关时兜底打开 creator
  const anyOn =
    config.series || config.realtime || config.creator ||
    config.totals.pageviews || config.totals.visitors || config.totals.sessions ||
    Object.values(config.breakdowns).some(Boolean);
  if (!anyOn) config.creator = true;

  return config;
}
```

白名单合并，schema 外的键一律丢弃；「全关兜底」在创建和编辑两个入口都生效。

## 8. 上报链路

### 8.1 处理顺序

| 步 | 动作 | 失败 |
|---|---|---|
| 1 | 路由分流（GET/POST/OPTIONS） | 400/204 |
| 2 | GET 取 query；POST 校验 `content-length ≤ 4096` 并解析 JSON | 413/400 |
| 3 | `token` 形态校验 `/^[A-Za-z0-9_-]{20,80}$/` | 400 |
| 4 | **限流** `analy_limiter`，key `evt:${ip}` | **201 空 body** |
| 5 | 按 token 查 `analytics_sites_v2` | 404 |
| 6 | `normalizeDomain(body.d)` 是否属于 `domains` | 403 |
| 7 | UA 解析，命中 `BOT_RE` | 204 |
| 8 | `new URL(body.u)` | 400 |
| 9 | 计算 `visitor` 哈希 | — |
| 10 | `INSERT analytics_events_v2` | 500 |
| 11 | 返回 | 204 |

限流放在「token 形态校验之后、查库之前」：伪 token 洪水也消耗配额，同时不触发 D1。**同时移除现有的 `env.limiter` 上报调用**，上报只走 `analy_limiter`。

### 8.2 限流与 201

```js
const ip = request.headers.get("cf-connecting-ip") || "0.0.0.0";
if (env.analy_limiter) {
  const { success } = await env.analy_limiter.limit({ key: `evt:${ip}` });
  if (!success) {
    if (env.DEBUG) console.warn("[analytics] ingest_dropped", { ip });
    const headers = { ...CORS_OPEN };
    if (env.DEBUG && request.headers.get("x-ay-debug") === "1") headers["x-ay-drop"] = "1";
    return new Response(null, { status: 201, headers });
  }
}
```

- 20 次 / 10 秒；`analy_limiter` 只服务上报，统计与列表不占这份配额。
- 超限回 201 而非 429：正常 SDK 不会重试，攻击者无法从状态码判断是否被限，数据直接丢弃，零存储成本。
- **边界要说清**：Cloudflare 的 Rate Limiting 按 colo 计数，不是全局，换 colo 可绕过；201 只降低攻击收益，不能替代 WAF / Bot Fight Mode。
- **可观测性**：201 让外部无法区分「成功」与「被丢弃」，内部必须有日志：`env.DEBUG` 全量，生产按 `hash(ip + 分钟) % 100 === 0` 采样 1%。
- 本地 `wrangler dev` 没有该 binding 时自动跳过。

### 8.3 多域名校验

```js
function getSiteDomains(site) {
  let list = [];
  try { list = JSON.parse(site.domains || "[]"); } catch { list = []; }
  if (!Array.isArray(list) || !list.length) list = [site.domain];
  return list.map(normalizeDomain).filter(Boolean);
}

const allowed = getSiteDomains(site);
const domain = normalizeDomain(body.d);
if (!domain || !allowed.includes(domain)) {
  return new Response(null, { status: 403, headers: CORS_OPEN });
}
```

`ref` 的「排除自身」判断也用 `allowed`，否则多域名站点会把自己的另一个域名算成外链来源。

### 8.4 会话

- `session_id` 由客户端每次页面加载生成 12 hex，SPA 路由切换不重置。
- `sessions` = `COUNT(DISTINCT session_id)`，仅计 `session_id <> ''`，避免旧版 SDK 把 sessions 计成 1。

### 8.5 请求字段映射

| 请求键 | 列 | 处理 |
|---|---|---|
| `t` | `site_token` | 形态 + 存在性 |
| `n` | `name` | 缺省 `pageview`，`clamp 64` |
| `u` | `path` | `pathname`，`clamp 512` |
| `r` | `ref` | 仅 host，排除自身，`clamp 255` |
| `w` | `screen` | 分桶 |
| `s`（新） | `session_id` | 12 hex，非法则 `''` |
| `tp`（新） | `touch_points` | 0/1/2/5/10，其余 0 |
| UA | `browser`/`os`/`device`/`*_version` | `parseUa` + 捕获组 |
| `cf.country` | `country` | `clamp 8` |
| `cf.regionCode` | `province` | 映射不到留空 |
| URL query | `utm_*` | 5 个，各 `clamp 255` |

## 11. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 新表为空、旧数据未搬 | 目录与面板为空 | 迁移前公告；DDL 与部署集中完成 |

| 限流按 colo | 分布式攻击可绕过 | 不宣称「全局限流」；配合 Bot Fight Mode |
| 201 掩盖故障 | 无法区分丢弃与成功 | 采样日志 + `x-ay-drop` 调试头 |
| `cf.regionCode` 取值不确定 | 省份维度可能为空 | 上线前采样验证；映射不到留空，不阻塞 |
| `creator` 锁定仅前端 | 直接调接口可绕过 | 单人自有服务可接受；要硬约束需服务端开关，本期不做 |
| D1 单库写串行 | 域名唯一性有极小竞态 | 站点数 ≤5/人，接受；强一致方案见 §11.1 |

### 11.1 域名强一致的备选（不默认采用）

影子表 `analytics_site_domains(domain PRIMARY KEY, site_id)`，创建/编辑时 `INSERT ... ON CONFLICT DO NOTHING`，比对 `meta.changes`，不等即回滚并返回 409。多一张表的维护成本，本期站点量级不需要。

## 12. 已定决策

| 决策 | 结论 |
|---|---|
| 分享配置不允许全关 | 接口兜底：全部为 false 时强制 `creator=true`；前端 `creator` 默认勾选并锁定，保证不会出现空页面 |
| 创建者展示 | 作为 `share_config.creator`，默认 `true`；详情接口按配置返回 `creator_username`，关闭时为 `null`；owner/admin 始终可见 |
| `creator` 勾选锁定 | 前端创建/编辑时默认勾选 + 禁用；开发者选项 `creatorControl` 解锁后可改 |
| 管理员看到全部站点 | `public` 区块直接返回全部（含他人 private），不做标记、不加接口、不做特殊渲染 |
| 管理员 `mine` 区块 | 只包含 `user_sub = 1` 的站点 |

> `creator` 锁定只在前端：直接调接口传 `creator:false` 仍会生效（单人自有服务，不加服务端白名单）。这是有意取舍。
